# 墨战（project8）需求文档

> 水墨风 State.io 类 RTS 城池攻防 + 战术卡牌 · 纯前端单机版
> 版本 v1.0 · 2026-10-06 · 配套：[架构设计](./架构设计.md) · [可视化原型](./prototype.html)

---

## 1. 项目概述

### 1.1 背景

墨战是一款水墨风格的 2D 城池攻防策略游戏，核心玩法与《State.io》同源：以颜色（墨色）为代表阵营，开局拥有一座城池，城池自动产兵，通过派兵攻占其余城池扩大产兵网络，最终占领全部敌方城池取胜。墨战的差异化在于**卡牌策略层**（火攻、护盾、借刀杀人等战术卡）与**水墨世界观**（墨色相溶、宣纸、印章、楷体）。

### 1.2 本期目标

| 项 | 内容 |
|---|---|
| 平台 | 浏览器（桌面 + 移动端），纯前端零依赖单文件 HTML，双击即玩 |
| 模式 | 快速对战（1v1 / 1v2 / 1v3 AI）+ 闯关（10 关递进解锁） |
| 单局时长 | 3~5 分钟 |
| 核心体验 | 「框选—派遣—扩张」的微操快感 + 卡牌临门一脚的博弈感 + 水墨视觉氛围 |
| 明确不做（远期规划） | 日卡养成 / 抽卡商城、在途部队互战、动态地形（河流改道等）、皮肤系统（**联机对战已交付：v1.26 联机重做、v1.39 房间码**） |

### 1.3 用户与场景

- 碎片时间玩家：手机竖屏/横屏、桌面浏览器，随时开一局。
- 策略玩家：通过屯兵列阵、卡牌组合实现以弱胜强。

## 2. 玩法需求

### 2.1 核心规则

| 编号 | 规则 |
|---|---|
| R1 | 地图由 8~14 座城池构成，分为：己方 1 座、每名 AI 1 座、其余中立（墨灰色） |
| R2 | **被占领的城池**随时间自动产兵，产速与容量由等级决定（见 2.4 数值表）；**中立城不产兵**，驻军固定（v1.4） |
| R3 | 派兵攻击敌方/中立城池：驻军与来犯部队互耗；**来犯兵力 > 驻军时城池易主**，剩余兵力成为新城防，等级保留 |
| R4 | 派兵至己方城池为增援：直接并入驻军；若驻军 ≥ 升级所需，**自动扣兵升级**（Lv3 封顶），溢出部分保留至容量上限 |
| R5 | 胜利：地图上不存在敌方城池（中立城不强制）；失败：己方城池数归零（在途部队不延续寿命） |
| R6 | 屯兵列阵：框选己方城池后点击**空地**，所选部队出城在该点列阵待命；阵列可被再次框选派遣；**屯兵永久驻守，不再散逸**（v1.22 移除原「每 5 秒散逸 1 兵」规则；屯点只在兵被派光或被敌军打光时消失） |
| R7 | 阵列与城池不发生战斗交互（位置公开，风险自负——蓄兵是双刃剑） |
| R8 | **在途互战（墨色相溶）**：不同阵营的在途部队行军途中相遇（距离 ≤ 16 虚拟像素）即互相湮灭，双方按较小兵力扣减，全灭一方消失；胜出部队继续向原目标行军 |
| R9 | **过城开战（v1.23）· 守军清空即接管（v1.36）**：在途部队行军途中经过**敌方 / 中立**城池即自动开战——双方按较小兵力互耗（`min(部队兵力, 城池驻军)`）；**互耗后守军被清空（或本就是空城）即顺手接管**，走与抵达完全相同的 `occupyCastle`；守军还在则只是擦过（拿下有兵的城仍需明说「打这座城」，R3 不变）。己方城不拦截；护盾中的城免疫并给出提示；**当前目标城交给抵达结算**，同一次行军不被结算两次。v1.35 及以前「只互耗、永不占领」，表现为「守军被我打光了城还挂敌旗」 |
| R10 | **伏兵（v1.24）**：「伏击」给**己方城池**设伏（`ambushT` 12 秒 / `ambushN` 杀伤数）。异主部队**抵达**该城时，先被伏兵吃掉 `min(兵力, ambushN)`；若被吃光则不再结算抵达。**伏兵一次性**——触发即清零；护盾分支先于伏兵返回（开盾的城不吃伏兵） |
| R11 | **瘟疫（v1.24）**：「瘟疫」给**敌方城池**上 `plagueT`（8 / 12 秒）。期间该城**停产**且每秒流失 `PLAGUE_RATE`（2）兵；到期自动恢复。与「虚弱」（产速减半）区分开——虚弱只是变慢，瘟疫是净减员 |
| R12 | **临时塔（v1.24）**：「连弩」给**己方城池**架一座 2 级箭塔，`tempT` 秒（12 / 18）后**自动拆除**；已有塔的城不再架设（不覆盖玩家的永久塔）。塔的开火/图标/冷却完全复用既有塔逻辑 |
| R13 | **摧塔（v1.24）**：「摧塔」把**敌方城池**的塔降 `v` 级（1 / 2），降到 0 级即摧毁（`tower = null`）。无塔的城打出无效（目标仍合法，只是无事发生） |
| R14 | **断粮（v1.24）**：「断粮」给**除自己外所有阵营**上 `effects.slowT`（8 / 12 秒），行军速度 × `SLOW_MUL`（0.5）。与「疾行」（己方 ×2）对称，是唯一的**群体减速**手段 |
| R15 | **伤亡记账（v1.25）**：`sim.stats.loss[阵营]` 纯累加，覆盖抵达互耗、在途遭遇、阵列迎敌、过城开战、塔火（含溅射）、火攻、箭雨、伏兵、瘟疫九类减员。**不消耗任何随机源、不参与任何判定**——只喂给战报与生涯统计；双方互耗的场合两边各记一份（语义天然对称） |
| R16 | **难度四档（v1.25）**：`DIFF` 在既有 `easy/normal/hard` 之上新增 `master`（宗师）。**既有三档数值一字不动**（否则全部平衡断言漂移），UI 只做中文标签映射（休闲/标准/困难/宗师）。四档参数单调：决策间隔↓、失误率↓、`minPool`↓、`cardChance`↑、`cardLv`↑、`nearW`↑；宗师 `cardLv=3` 放开全卡池 |
| R17 | **自定义对局参数（v1.25）**：`opts.custom = { inkStart, capMul, prodMul }` + `goal:{type:'time', sec}`。**不传 custom 时与 v1.24 逐字节等价**；`capMul/prodMul` 直接乘进已有的 `sim.mods`（不新增字段）。限时到点按「占城数 → 其次总兵力」判胜，多者胜，完全相同判玩家负（鼓励主动出击） |
| R18 | **新手引导（v1.25）**：首次进入自动起九步分步引导；每步「四面遮罩挖洞」高亮一个真实 UI 元素并讲解；可**跳过**，进度写 `ink.tut`，未完成时菜单给「继续引导（第 n 步）」**断点续接**；引导与 `mode` 正交（不改写任何既有状态）；`wait` 步骤 90 秒未等到自动过，防卡死 |
| R19 | **战报（v1.25）**：对局结束产出战报——双方兵力曲线（0.5 秒一采样，上限 600 点）、关键事件时间轴（按重要度取前 12 条，同类 3 秒节流）、用时与双方折损/占领/用卡统计。**只留内存不落盘**（零配额占用），结算页「查看战报」进入，战报页提供**再战此局 / 返回菜单** |
| R20 | **三槽位存档（v1.25）**：三个档位读写删，存**元进度**（进度、最快纪录、战绩、卡组、收集、生涯、成就、设置）+ **最近一局种子**，「一键复现同一开局」。**不存棋盘中局**——`sim` 含三路随机源函数与互相引用，JSON 化不可靠；「种子 + 配置」才是可复现的最小充分条件 |
| R21 | **成就（v1.25）**：12 条成就，含解锁条件与进度展示；未解锁项名字隐藏为「？？？」并显示 `x / y`。数据源是 `ink.life` 生涯统计（块2 自算，不动块1）；**联机与教学局不计入生涯**，避免刷成就 |
| R22 | **教学局（v1.25）**：引导末步开一局真实快速对战（`opts.tutorial = true`），照常给战利品，但**不计入战绩 / 闯关进度 / 最快纪录 / 生涯统计** |
| R23 | **快照同步补齐（v1.26）**：快照新增 `fx`（断粮 slowT）/ `pt`（屯田 prodT）两个效果数组，城池行**尾部追加** `ambushT / ambushN / plagueT / 塔临时剩余` 四个字段（尾部追加 = 新旧版本可互解）。根因：客机航位推算走 `Sim.armySpeed`，它要读 `slowT`；缺了它断粮期间客机按原速推算，位置持续超前再被快照硬拉回 = 肉眼可见抖动 |
| R24 | **短联机码（v1.26）**：联机码三步无损瘦身 —— ① `sdpMin` 按白名单裁掉数据通道用不到的行（extmap / ice-options 等）；② 令牌表把 `a=candidate:` 等高频前缀与候选行固定短语换成单字符（**只作用在 SDP 上**，避免与 JSON 自己的 `{}` 撞车）；③ base64url（去填充、URL 安全，链接里无需转义）。浏览器支持 `CompressionStream('deflate-raw')` 时再压一层。码首字符区分版本：`z`=压缩码 / `s`=裁剪码 / 其余=旧版整份 base64（**向后兼容仍可解**）。实测缩短 37%（裁剪）~ 60%（压缩） |
| R25 | **连接过程可视化（v1.26）**：`#pvpStat` 跟随 ICE 阶段实时播报（建立 / 协商 / 已连接 / 中断 / 失败），**20 秒未连通明确报超时**并给出可操作建议（换同一 Wi-Fi 或手机热点）；`failed` / `closed` 立刻给原因。`disconnected` 多为瞬时抖动，**交给心跳宽限处理**，不直接判死 |
| R26 | **心跳与断线宽限（v1.26）**：每秒一次 `pg`/`po` 测往返延迟（顶栏实时显示，≤80ms 绿 / ≤200ms 金 / 更高朱砂）；`DataChannel.onclose` 在异常网络下可能长时间不触发，故 **连续 4 秒无下行包即判定失联** → 暂停对局 + **10 秒重连宽限**（主机不能趁对手掉线单方面推进），重连即续、超时走终止流程 |
| R27 | **房主配置与客机暂停（v1.26）**：等待室可设**地图 / 节奏 / 限时**并随 `cfg` 消息实时同步给客机（客机只读）。**PVP 双方都是人、没有 AI，难度选项没有意义，故不提供**。客机可发 `pausereq` **请求暂停**——决定权仍在房主（避免客机单方面冻结对局），20 秒无响应给提示 |
| R28 | **再战双向确认与战绩口径（v1.26）**：再战改为**双向确认**——任一方点「再来一局」只登记意愿，双方都点头才由房主发车（此前客机一按就把主机拽进新局）；20 秒无人响应提示可先返回菜单。**联机战绩独立记账**（`ink.netrec`）：单机走 `record` + `life`，联机只走 `netRec`，结算页展示「联机战绩」，口径统一、互不污染 |
| R29 | **双指缩放与平移（v1.27）**：双指张开 / 捏合缩放战场（1~3.2×），双指拖动平移视野；桌面滚轮以光标为锚点缩放。**缩放平移只走双指**，单指的点选 / 派遣 / 框选语义一字不改，两条链路永不打架。第二指落下即撤销单指正在进行的拖拽 / 框选，`pointercancel` 与抬指都必须清空触点 |
| R30 | **竖屏布局与视野补偿（v1.27）**：手机竖屏画布比例由 16:9 放宽到 **1.35**，基准 fit 由 contain（留黑边）改为 **cover（铺满）**，棋盘占屏高 25% → 33~40%（8 档机型实测）。铺满必然裁掉两侧，故**视野偏离默认时左下角自动浮出缩略图**（全图城池点 + 朱砂视口框），左上角 **⤢** 徽标一键复位（快捷键 `0`），开新局自动复位 |
| R31 | **入门难度档（v1.27）**：`DIFF` 新增 `novice`（既有的 easy/normal/hard/master **一字不动**），取向不是「打得更慢」而是「**敢打但打不准、也守不住**」——出兵门槛极低（minPool 5 / buffer 0.5）保证家里不留厚壳，六成决策选错目标、完全不用牌、不拦截。实测第 1 关弱玩家胜率 48% → 64%，我方被占城数 3.5 → 2.2 |
| R32 | **十五关梯度抹平（v1.27）**：重排为「入门 ×2 → 休闲 ×4 → 标准 ×4 → 困难 ×5」，敌方初始加成改 0/5/10/15/20 五档细步；**相邻关卡最多「敌数 +1 / 难度 +1 档 / 加成 +5」**，消掉原先「第 6 关 0→10」「第 9 关休闲→困难 + 敌数 2→3」两处跳崖；第 4 关不再「敌数 +1」与「城池 +1」同时发生，第 7 关限时 180 → 240 秒 |
| R33 | **触屏操控放大（v1.28）**：点按/拖动阈值与命中容差全部改按 **CSS 像素**标定（`mapPerCss()` 随缩放换算），粗指针（手指）容差再放大——兵级命中 11 CSS px、部队/阵列 9 CSS px、点按 vs 拖动判定位移 22 CSS px（手机竖屏旧值仅相当于 5~7 CSS px，表现为「点不中兵、轻抖就误出兵」）；**胖手指补偿**：触屏点按按「落指」位置判定意图（按下到抬起常见 10~20px 滑动，按抬起点命中会落空）；屏内方向键按钮粗指针下放大到 44px（≥最小触控热区）；桌面（鼠标）阈值语义不变，打桩断言逐位不漂 |
| R34 | **方向键从「城池」直接起步（v1.29）**：选中**己方城池 / 阵列**后按 `WASD` 或屏内方向键 = **直接派兵朝该方向行军并接管**（此前 `manualLaunch` 只认「点中的兵」，选中城池按方向键只弹提示 + 一声错误音；而电脑上一个环兵的命中直径仅约 7 CSS px，手机端屏内方向键在选中城池时**根本不显示**）；**屏内方向键在选中己方城池/阵列时即浮出**（选中敌方城池仍不浮出）；**什么都没选中时**按方向键自动接管**最近的己方在途部队**（此前同样是死路）。实测：起步延迟 32 ms、改向 32~64 ms、松开 0 ms，选中城池按 W → 48 ms 接管、16 ms 后开始移动 |

| R36 | **连续指令（v1.31）**：单兵 / 部队操控链路里，**移动 → 驻扎 → 再移动**不必重新点选。三处改动：① `dispatch(sources, target, keep)` 新增 `keep` 参数，操控链路（manualLaunch / manualTick）传 `true` **不清空选择**，普通派遣（点目标 / 回防 / 点空地列阵）仍一律清空；② 认领新部队时 `selection = [{k:'a', id}]`（退出驻扎 = 选中在途部队）；③ 松手驻扎时置 `ctrl.settle`，部队抵达消失后 `manualSettle()` 按最后位置认领新扎下的阵列并设为 `selection = [{k:'p', id}]`（**进入驻扎 = 选中阵列**）。部队若被歼灭（`settle = false`）一律不接管，避免误选旁边的阵列。连测三轮「驻扎 → 直接按键」全部成立；真机实测选中城池 → 按 W → 松手驻扎 → 不点任何东西直接按 ↑ 即继续行军 |

### 2.5 系统需求清单

- **对局系统**：地图生成（泊松盘）、固定步长模拟、战斗结算、胜负判定。
- **指挥系统**：点选/框选/派遣/列阵/比例切换（O1~O9）。
- **卡牌系统**：墨量、3 卡槽、摸牌循环、8 张卡效果与目标选择模式。
- **AI 系统**：三档难度，与玩家共用同一命令接口。

### 2.14 屯兵不再散逸（v1.22）

**背景**：原规则（R6）是「阵列每 5 秒散逸 1 兵，减到 0 即整点消失」。实测两个问题：① 单兵操控（O16a / O50~O55）松手驻扎 = 1 兵阵列，**约 5 秒后凭空蒸发**——玩家辛苦走位换来的兵白白没了，体验上等同于 bug；② 文档自相矛盾——架构设计不变量 3 写「`Camp.count ≥ 1`（散逸至 **1 为下限，不归零**）」，代码却是减到 0 直接 `filter` 删掉。玩家反馈「阵列里兵在慢慢变少、兵会自己消失」，故移除散逸。

| 编号 | 需求 |
|---|---|
| O71 | **取消散逸**：移除 `CFG.CAMP_DECAY` 与「每 5 秒 -1 兵」的步进逻辑——**屯兵永久驻守**，兵力不随时间流失。单步顺序里的「阵列散逸」环节改为「阵列计时」（只推进 `atkT` 攻击动作计时） |

| O73 | **数据结构瘦身**：`Camp` 去掉 `decayAcc` 字段（阵列创建与联机快照解码同步去掉），避免留下永远为 0 的死字段 |
| O74 | **文案同步**：玩法说明「要诀」里的「阵列每 5 秒散逸 1 兵」改为「**屯兵永久驻守**（不再自行散逸）」 |

### 2.15 过城开战（v1.23）

**背景**：原先只有「敌军经过**阵列**即战斗」（O15），部队经过**城池**却完全无视——玩家操控的兵从敌城身上走过去什么都不会发生，等于穿过一片空气；「墨色相溶」的拦路设定在城池这一侧缺了一半。

| 编号 | 需求 |
|---|---|
| O76 | **过城即战**：在途部队（含 AI 派出的、含手动操控的单兵）行军途中进入 `castleR(c) + armyR(a)` 范围且城池 `owner ≠ 部队 owner` → 立即开战，`kill = min(部队兵力, ⌊城池驻军⌋)`，双方各减；推 `clash` 事件（复用既有墨晕特效），城池 `hitT` 置位触发整环抖动 |
| O77 | **守军清空即接管（v1.36 改写）**：过城互耗后若 `⌊驻军⌋ < 1` 且部队仍有兵 → **接管该城**（`occupyCastle(sim, c, a, true)`：改归属 / 进墨 / 记战报 / 剩余兵力转驻军，部队带着剩下的兵继续行军）。**有守军时不占领**（R3 不变：想拿下有兵的城仍要明说），所以「大兵团路过顺手收走满编城」依旧不会发生 |
| O78 | **己方城不拦截**：`owner === 部队 owner` 的城池完全不响应，走位不被自己人卡住（含单兵操控穿城而过） |
| O79 | **护盾免疫 + 目标城不重复结算**：`shieldT > 0` 的城池免疫过城开战（护盾只对「以该城为目标」的来犯生效的语义在此保持一致）；**当前目标城跳过**，仍由抵达结算按 R3 一次结算完毕 |
| O80 | **空城：不开战但接管**：`⌊驻军⌋ = 0` 时**不互耗**（不会每帧刷 `clash` 事件），但兵力门槛为 0 已满足 → 直接接管（含「互耗同归于尽」时守军归零的情形） |
| O81 | **半径同源**：判定用的 `castleR()` 由逻辑块导出（`Sim.castleR`），渲染层改为复用同一函数——过城判定和画出来的城池必须是同一把尺子 |
| O82 | **文案同步**：玩法说明「要诀」写「行军经过敌方/中立城池会自动开战：守军被打光（或本就是空城）就顺手接管；守军还在则只是擦过，想拿下要点名攻打。己方城不拦你，护盾中的城免疫（会给出提示）」 |
| O83 | **不满足时给明确提示（v1.36）**：① 护盾中 → 「护盾未破 · 该城免疫过路部队」；② 兵力不足被守军吃掉 → 「兵力不足 · 过城部队被守军吃掉了」。提示经 `passHint()` 按「**同一支部队对同一座城只发一次**」节流（否则守军未清时每帧一条飘字） |

**平衡实测（A/B，60 局同种子，困难 vs 容易）**：困难 AI 胜率 72% → **63%**（仍 ≥ 60% 验收线），平均对局时长 153s → **142s**，无僵局。方向符合预期：行军成本上升，对进攻方（困难 AI）的削弱略大于防守方。

**v1.36 接管改动的平衡实测（A/B，n=160×2 种子族，困难 vs 容易）**：困难 AI 胜率 **58.1%→75.0%** / **71.7%→81.8%**（+10~17pp），平均时长 139s→134s / 140s→130s，僵局数不变（0 / 1），占领次数 +8%（其中约 20% 来自路过接管）。原因：强方更爱派兵穿行，顺手捡城的收益被放大。**试过「过路接管不给占城墨」想把差值压回去，实测无差异（75.0% / 81.8% 一字未变）**，故保持与抵达同口径。若后续嫌困难太强，该调的是 `DIFF.hard` 参数而不是接管规则。

| M2 | 信令：邀请/应答码（ICE 收集完毕的 SDP base64）。主机生成**邀请链接**（`?join=码`）发给朋友，朋友打开即预填；朋友回传**应答链接**（`?accept=码`），主机粘贴后完成连接——静态托管即可联机，无需自建服务器 |
| M3 | 同步模型：**主机权威状态同步**。主机是唯一模拟者，每 100ms 广播压缩快照（城池/部队/阵列/墨量/手牌/表现事件）；客机不跑模拟，渲染镜像并在快照间做部队航位推算 |
| M4 | 指令流：客机的派遣/卡牌指令发送给主机，经与本地完全相同的 `command/cardPlay` 接口执行。**v1.35 权威校验**：主机**不信任网络里的 `owner` / `type` 字段**，一律按「客机 = 2 号阵营」重建 `send` / `retarget` / `split` / `allout` / `castleUp` / `card` 指令（`ratio` 同时钳进 [0,1]）；块1 各指令还会再按 owner 校验城池/阵列/部队归属，伪造 `owner:1` 到此为止（此前 `send`/`retarget`/`split` 直接把 `d.cmd` 丢进 `Sim.command`，客机可伪造房主兵令） |
| M5 | 视角：客机 HUD（我城/敌城/墨量/手牌）、选中框、胜负判定（`over === mySide`）全部按本机阵营计算 |
| M6 | 暂停权：联机时暂停权在房主；房主暂停/继续同步客机显示「房主暂停了对局」 |
| M7 | 重开：任一方点「再来一局」→ 主机换种子重开并广播，双方同种子重建同图 |
| M8 | 断线：连接断开即对局终止，显示「断·连」结算并可返回菜单 |
| M9 | PVE 回归：单人（快速/闯关）行为与 v1.0 完全一致 |
| M10 | **离开页面不计失联（v1.35）**：监听 `visibilitychange`，任一方切后台/切标签都互发 `away` 包。**离开期间：不累计失联计时、不判定失联、不进重连倒计时、不终止对局**；并且**双方一起冻结**（沿用「主机不能趁对手掉线单方面推进」的原则，谁也别在对手离开时推进战局）。回来即自动继续：主机立刻补推一帧快照，客机发 `resnap` 主动索要。顶栏延迟指示显示「对手后台」（金色，区别于断线的朱砂） |
| M11 | **带宽口径（v1.35 实测）**：10Hz 全量快照在 8~14 城下为 **503B ~ 1033B/帧（≈5~10 KB/s）**，相邻帧仅 3/16 个字段变化 —— 带宽不是瓶颈，**不做增量/二进制快照**（收益换不来协议复杂度与兼容风险） |
