## 2. 构建与部署步骤

### 目标 A：静态托管平台（本次采用）

无「构建」环节，直接发布目录（`entryHtml` 必须给，目录里有多个 html）：

| 参数 | 值 |
|---|---|
| `directory` | `D:/2-work/javaCode/vibeproject/project8` |
| `language` | `static` |
| `entryHtml` | `inkwar.html` |
| `appName` | `墨战` |
| `domainPrefix` | `inkwar` |
| `appId` | `wbapp_Oxw6TogrMNVz4o51j4M1qv`（**v1.39 起必填**：与云服务绑定的同一个应用；省略会新建应用 → 域名变化 → 服务端 exact-Origin 校验失败 → 房间码全部失效） |
| `userAskedToPublish` | `true`（**必须用户当次明确说「上线」，否则工具拒绝覆盖线上链接**） |

托管侧会以静态方式服务目录（`python3 -m http.server "$PORT" --bind 0.0.0.0` 等价行为），无需自造 Node 服务器。
**重新发布 = 覆盖同一链接**（不会生成第二个 app，旧链接保持不变）。

### 目标 B：如果换成自有服务器 / 容器（等价命令，未采用）

```bash
# 单文件，无需构建，直接拷产物
scp inkwar.html user@server:/var/www/inkwar/index.html

# 或用任意静态服务器（必须是 $PORT 且 bind 0.0.0.0）
python3 -m http.server "$PORT" --bind 0.0.0.0
# docker 场景
# docker build -t inkwar . && docker run -e PORT=8080 -p 8080:8080 inkwar
# nginx 只需要：root /var/www/inkwar; index index.html; try_files $uri /index.html;
```

⚠️ 换自有域名时需要在 DNS 加一条 CNAME 指向托管域名；本工具不代管 DNS，需你提供域名与解析权限。

## 4. 回滚方案

**方案 1（推荐）：用备份文件重新发布**

```bash
cd /d/2-work/javaCode/vibeproject/project8
ls -la .workbuddy/backups/                       # 选一个回滚点
cp .workbuddy/backups/inkwar-v1.37-20261021-1215.html inkwar.html     # 回滚到 v1.37
# 想回到更早的 v1.35：inkwar-v1.35-20261020-1656.html（387,873 字节）
# 校验回滚点可用（可选但建议）
node tools/verify-sim.js && node tools/smoke-ui.js
# 再次发布（同一链接被覆盖，对外地址不变）
```

**方案 2：直接下线（对外停止服务）**

调用发布工具的 `action:"unpublish"`，线上链接立即失效。**注意：下线是删除对外访问，不是回退版本**——
要恢复服务必须重新 `deploy`。

**注意事项**

- **不要用 git 回滚**：`git log` 最新提交是 `d14e470`（v1.9），远旧于线上任何版本，`git checkout` 会把线上打回远古版本。
  发布前请务必确认工作区文件已全量写盘（工具按目录原样上传）。
- **无服务端状态**：回滚不影响任何用户数据（全在各自浏览器 `localStorage`），也不会有数据库需要回滚/补偿。
- **旧链接不变**：重新发布覆盖的是同一个 app，已分享出去的链接继续有效。
