# 响应式布局说明

本文记录《泡泡对战》的断点定义、各档位的元素排列与显示优先级，以及溢出、画布缩放、触控和可读性方面的具体处理方式。

实现分布在三处：`public/style.css`（断点与排版）、`public/js/layout.js`（棋盘尺寸求解、视口变量、能力标记）、`public/js/render.js`（画布按 CSS 尺寸做视觉降级）。

---

## 1. 设计原则

1. **棋盘永远完整可见**：它是唯一不可裁剪、不可滚动的元素，任何视口下都按 15:13 等比缩放，宁可变小也不截断。
2. **触控优先**：手指要按的控件（摇杆、放弹键、主按钮）不参与"空间不够就缩"的降级，最小 44×44。
3. **按优先级降级，而不是整体缩小**：空间不足时先砍信息（对手属性、提示文案），再缩字号，字号有下限。
4. **断点由内容决定**：不是"手机/平板/电脑"，而是"什么时候当前排列放不下了"。

---

## 2. 断点定义

### 2.1 宽度断点

| 断点 | 宽度 | 典型设备 | 关键变化 |
| --- | --- | --- | --- |
| `xs` | `< 480px` | 手机竖屏（320 / 390 / 430） | 创建/加入按钮**纵向堆叠**；隐藏"房间"二字与网络文案；对手状态卡只留头像+名字；正文降到 12px 下限 |
| `sm` | `480–767px` | 大屏手机、折叠屏外屏 | 创建/加入恢复同行；正文 12.5px；棋盘上限 560px |
| `md` | `768–1023px` | 平板竖屏 | 面板加宽到 440px；棋盘上限 680px；HUD 单行铺开 |
| `lg` | `1024–1199px` | 平板横屏、小笔记本 | 棋盘上限 700px；触屏时摇杆移到**左右两侧** |
| `xl` | `≥ 1200px` | 桌面 | 棋盘与 HUD 变**左右两栏**（HUD 竖排 190px） |
| `2xl` | `≥ 1440px` / `≥ 1600px` | 桌面宽屏 | 棋盘上限 780 → 880px，HUD 栏加宽到 200 / 216px |

### 2.2 高度断点（与宽度正交）

| 条件 | 目的 | 变化 |
| --- | --- | --- |
| `landscape and max-height: 560px` | 手机横屏（最紧张的一档） | 顶栏压到 28px；HUD 只显示自己的属性；面板去掉操作提示、内边距收紧；摇杆左右分列 |
| `landscape and 561–900px` + 触屏 | 平板横屏、触屏笔记本 | 摇杆同样左右分列，但顶栏/HUD 保持正常尺寸——否则底部 158px 的摇杆区会把棋盘压小一截 |
| `min-height: 561 and max-height: 720px` | 1366×768 笔记本 | 上下留白与顶栏收紧，棋盘多出约 20px |

### 2.3 能力与偏好查询

| 查询 | 用途 |
| --- | --- |
| `(pointer: coarse)` / `(any-pointer: coarse)` | 显示虚拟摇杆与触屏操作提示；关掉 `:hover` 的粘滞效果；把分段控件、步进器抬到 36–42px |
| `(prefers-reduced-motion: reduce)` | 关闭浮动、弹入等装饰动画，只保留状态切换 |
| `(prefers-contrast: more)` | 加深分隔线与说明文字，卡片补描边 |

## 3. 各断点的排列方式与显示优先级

### 3.1 显示优先级

空间不足时，从 P5 往 P0 依次裁剪：

| 级别 | 内容 | 降级方式 |
| --- | --- | --- |
| **P0** | 棋盘 | 绝不裁剪，只等比缩小 |
| **P1** | 摇杆 / 放弹键 | 触屏上不隐藏，只改位置（下方 ↔ 两侧） |
| **P2** | 自己的状态卡（名字 + 火力 + 炸弹数） | 始终完整 |
| **P3** | 其他玩家状态卡 | 先去掉属性块，只留头像 + 名字；横屏再隐藏 AI 角标 |
| **P4** | 顶栏信息 | 依次去掉"房间"二字 → 网络状态文字（只留颜色圆点） |
| **P5** | 操作提示文案 | 手机横屏的对局面板里直接隐藏 |

### 3.2 元素排列

| 区域 | `xs` 竖屏 | `md` 平板竖屏 | 横屏触屏（≤900 高） | `xl` 桌面 |
| --- | --- | --- | --- | --- |
| 顶栏 | 品牌 + 计时 + 房间号 + 状态点，gap 6px | 品牌 + 全部信息 | 高度压到 28–34px | 高度 42px，左右留白加大 |
| 主区 | 棋盘居中，宽度贴边（`--gutter: 10px`） | 棋盘居中，上限 680px | 棋盘垂直居中，左右各留 148–164px 安全带 | 棋盘 + HUD **左右两栏**，整组居中 |
| HUD | 棋盘下方，自动换行 2 行 | 棋盘下方，单行 4 卡 | 棋盘下方单行 | 棋盘右侧竖排，卡片占满 190–216px |
| 触控 | 左下摇杆 144px、右下放弹键 92px（高屏） | 左下 132px / 右下 82px | 摇杆左中、放弹键右中，垂直居中 | 隐藏（鼠标键盘） |
| 面板 | 贴边 16px，内边距 20/16 | 440px 宽 | 480px 宽，内边距压缩到 14/18 | 440px 宽 |
| 创建/加入 | 纵向堆叠，各占整行 | 同行 | 同行 | 同行 |

## 4. 棋盘尺寸是怎么算出来的

早期用 `width: min(672px, 100%, calc((100vh - 200px) * 1.174))` 这类 vh 魔法数字，问题很明显：`100vh` 在移动端包含地址栏、HUD 换行后高度会变、4 人局比 2 人局多一行——任何一个变化都会让棋盘被裁或被压得过小。

现在改为**运行时求解**（`public/js/layout.js`）：

```
可用宽 = stage.clientWidth − stage 左右 padding
可用高 = stage.clientHeight − stage 上下 padding − 触控预留（由 CSS 的 #app padding 表达）
棋盘宽 = min(可用宽 − HUD 占位, (可用高 − HUD 高度 − 间距) × 15/13, --board-max)
```

几个要点：

- **`--board-max` 是唯一的尺寸真源**，写在 CSS 的断点里（560/680/700/780/880），JS 读取它，不需要在两处维护同一组数字。
- **两趟求解**：HUD 的宽度依赖棋盘宽度，换行后高度会变，所以设完宽度后再量一次 HUD，必要时重算一次。
- **只在尺寸真变化时才写入**（差值 ≥1px 才 `setProperty`），配合 `ResizeObserver` 不会产生抖动或死循环。
- **CSS 侧仍保留 `max-width` 兜底**：JS 被禁用时退回 `width: 100%`，棋盘最多贴边，不会溢出。
- 触发重算的时机：窗口 resize、`orientationchange`（延后 120ms 等系统尺寸稳定）、字体加载完成、界面切换、HUD 内容变化。

实测结果（画布 CSS 尺寸）：

| 视口 | 棋盘 | 视口 | 棋盘 |
| --- | --- | --- | --- |
| 320×568 | 292×253 | 768×1024 | 668×579 |
| 390×844 | 362×314 | 1024×768 | 652×565 |
| 430×932 | 402×348 | 1366×768 | 708×614 |
| 812×375（横） | 340×295 | 1440×900 | 768×666 |
| — | — | 1920×1080 | 868×752 |

比例全部为 1.154（= 15/13），偏差 < 0.001。

## 5. 内容溢出

| 场景 | 处理 |
| --- | --- |
| 页面整体 | `html, body { overflow: hidden }` + `#app { height: 100dvh }`：游戏不需要页面滚动，也避免移动端下拉刷新/橡皮筋误触 |
| 面板内容超长（如 320px 宽打开混合模式配置） | `.panel { max-height: 100%; overflow-y: auto; overscroll-behavior: contain }`，滚动只发生在面板内部，"快速匹配"按钮仍在首屏可见区内 |
| 长玩家名 | `.pcard .nm` / `.players .nm` 单行省略号 + `min-width: 0`（flex 子项默认 `min-width: auto` 会撑破容器，这是最常见的溢出原因） |
| 换行文本 | 说明类文字加 `overflow-wrap: anywhere`，中文长串/英文长串都不会顶出卡片 |
| 顶栏 | 容器 `min-width: 0`，房间号 `text-overflow: ellipsis`，窄屏再隐藏标签文字 |
| Toast | `width: max-content; max-width: min(86vw, 460px)`，多行居中，不再顶出屏幕 |
| 横向溢出兜底 | 断点内所有 `flex` 子项显式 `min-width: 0`；自动化测试逐视口断言 `documentElement.scrollWidth ≤ innerWidth` |

## 6. 画布（图片类元素）的缩放

项目没有位图资源，所有图形由 Canvas 绘制，缩放问题集中在画布上：

- **固定内部分辨率**：660×572（15×13 格 × 44px），`canvas.width/height = 逻辑尺寸 × min(devicePixelRatio, 2)`，在 Retina 上不糊、又不会让 4K 屏付出 3–4 倍填充成本。
- **固定比例**：`#board { width: 100%; height: auto; aspect-ratio: 15 / 13 }`，由 CSS 等比缩小，任何尺寸下都不变形（实测各视口比例恒为 1.154）。
- **视觉降级**：`render.js` 每帧读一次 `canvas.getBoundingClientRect().width / 660` 得到 `viewScale`。当 `viewScale < 0.58`（手机横屏、320px 小屏）时，角色头顶的名字会小到 5px 变成一团噪点，此时**不再画名字**，只给自己画一个蓝色向下箭头定位；名字信息由下方 HUD 承担。
- **不缩放 UI 文字**：摇杆、按钮、面板都是 DOM，按断点给固定尺寸，不跟着画布一起缩——这是"游戏画面缩放"和"界面缩放"必须分开处理的原因。

## 7. 触控交互细节

| 问题 | 处理 |
| --- | --- |
| 点击目标太小 | 所有按钮 `min-height: 44px`；摇杆按钮 44×44（高屏手机放大到 48）；放弹键 82–92px；分段控件在触屏上抬到 36px |
| 300ms 点击延迟 | `body { touch-action: manipulation }`，保留滚动与双指缩放 |
| 按住摇杆时页面跟着滚 | `.tbtn { touch-action: none }` + `pointerdown/up/cancel/leave` 四事件，指针移出按钮即视为松手 |
| 按方向键时选中文字 | `user-select: none` + `-webkit-tap-highlight-color: transparent` |
| 拇指区被遮挡 | 竖屏时 `#app` 底部预留 158px 给摇杆；横屏时改为在 `.stage` 左右各留 148–164px，摇杆垂直居中——两种布局都不会压住棋盘 |
| 刘海/圆角/手势条 | `viewport-fit=cover` + `env(safe-area-inset-*)` 参与 `#app`、`.overlay`、`.touch` 的内边距计算 |
| 触屏上 hover 粘住 | `@media (pointer: coarse)` 取消 `.btn:hover` 的阴影与描边变化 |
| 软键盘顶起界面 | `visualViewport.resize` → 写入 `--vvh`，`.overlay { height: var(--vvh) }`；输入框聚焦后 `scrollIntoView({ block: 'center' })` |
| 输入框自动放大 | `input { font-size: 16px }`（iOS 对 <16px 的输入框会在聚焦时放大整页） |

## 8. 文字可读性与可访问性

### 8.1 排版

- **字号下限**：正文类文字（`.hint` / `.sub` / `.lineup` / `.roomcfg`）在所有断点 ≥ 12px；徽标/角标（`.pcard .st i`、`.tag`）≥ 10.5px 且只承载次要信息。
- **行高**：说明文字 1.6–1.7，按钮内文字不折行。
- **对比度**：说明文字由 `#8ba1b5`（约 2.7:1）改为 `#64798d`（约 4.6:1），满足 WCAG AA；徽章文字统一加深到 4.5:1 以上。
- **标题自适应**：`font-size: clamp(25px, 6.4vw, 32px)`，窄屏不换行、宽屏不显小。

### 8.2 无障碍

- **允许缩放**：`viewport` 去掉了 `maximum-scale=1` / `user-scalable=no`（WCAG 1.4.4）。
- **焦点可见**：`:focus-visible` 统一 3px 蓝色描边（输入框用 box-shadow 焦点环，避免双环）；按钮全部可用 Tab 到达。
- **语义**：三个界面是 `role="dialog" aria-modal="true"` + `aria-labelledby`；分段控件是 `role="group"` 且用 `aria-pressed` 表达选中态（随点击同步更新）；图标按钮（四向键、放弹、加减 AI）都有 `aria-label`；Toast 是 `role="status" aria-live="polite"`。
- **焦点管理**：进入对局时主动 `blur()`，避免空格既放炸弹又重复触发按钮；界面切换时把焦点送到该面板的主按钮；首次进入首页不自动聚焦（否则手机会立刻弹出键盘）。
- **动效偏好**：`prefers-reduced-motion` 下动画时长压到 0.001ms，装饰性气泡直接隐藏。
- **高对比度**：`prefers-contrast: more` 下加深分隔线与次要文字，卡片补 1.5px 描边。

## 9. 验证

`node test/responsive.js` 用 Playwright 驱动真实 Edge，覆盖 9 个视口（320/390/430 竖屏、812×375 横屏、768×1024、1024×768、1366×768、1440×900、1920×1080），逐项断言：

- 断点标记、无横向溢出、触屏识别
- 首页面板完整落在视口内、模式按钮不溢出、正文 ≥12px、输入框 ≥16px、主按钮 ≥44px
- 对局中棋盘完整可见、比例 15:13、不超出舞台、不与 HUD/摇杆重叠（宽屏 HUD 在右，其余在下方）
- 横屏摇杆在棋盘左侧、放弹键在右侧；竖屏摇杆在棋盘下方；放弹键 ≥64px、摇杆按钮 ≥44px
- 无页面报错

当前结果：**184 项断言全部通过**。对应截图见 `shots/r-<宽>x<高>.png`（对局）与 `shots/r-home-<宽>x<高>.png`（首页）。
