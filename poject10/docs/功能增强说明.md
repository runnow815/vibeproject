# 泡泡对战 · v1.1 功能增强说明

> 更新日期：2026-10-20 · 版本 1.1.0
> 本文说明 v1.1 新增功能的范围、目标用户、预期效果，以及配套的输入校验、异常处理、边界情况与性能考量。设计依据见 [需求文档](./需求文档.md)（FR-11…FR-15）与 [架构文档](./架构文档.md)（模块视图 C-2/C-6、协议 3.5、ADR-11…ADR-15）。

## 1. 总览

v1.1 在**不改动既有核心逻辑**（`server/game.js` 零改动、快照字段零改动、`server/bot.js` / `server/lineup.js` 零改动）的前提下，交付一个「体验增强包」：

| 能力 | 内容 | 主要文件 |
| --- | --- | --- |
| 房间聊天 | 8 条快捷语 + 自由输入，仅等待阶段可用 | `public/js/chat.js`、`server/index.js`（chat 分支） |
| 邀请链接 | `?room=` 同步、复制链接、剪贴板降级 | `public/js/share.js` |
| 设置中心 | 音效/音量/减少动效/操作提示，本地保存 | `public/js/panels.js`、`public/js/store.js` |
| 本地战绩 | 最近 20 局、汇总统计、导出 JSON | `public/js/store.js`、`public/js/panels.js` |
| 输入校验与加固 | 校验层、令牌桶限流、payload 上限、容错 | `server/validate.js`、`server/index.js` |
| 模态层 | 焦点陷阱 / Esc / inert，防输入穿透 | `public/js/panels.js`、`public/js/main.js` |

## 2. 各功能的范围 / 目标用户 / 预期效果

### 2.1 房间聊天（FR-11）

- **范围**：仅房间 `waiting` 阶段；开局即禁用并清空；不做私聊、不做表情包、不做历史持久化。聊天广播走既有 `Room.broadcast`，**不新增玩家字段、不改动快照**。
- **目标用户**：2–4 人开黑的朋友局——"等我一下""开始吧"这类短句本来就是开黑高频需求。
- **预期效果**：等待准备的 10–30 秒不再干等；快捷语让不开麦的玩家也能沟通。

**协议**（新增 1 个上行 + 1 个下行消息，均为可选分支，旧客户端忽略即可）：

```
上行 { t:'chat', text:string }          // 客户端 → 服务端
下行 { t:'chat', id, name, color, text, at }  // 服务端 → 房间内所有人
```

### 2.2 邀请链接（FR-12）

- **范围**：房间页「复制邀请链接」；进房同步 `?room=` 到地址栏（`history.replaceState`，不产生历史记录）；`?room=` 打开页面只**预填不自动加入**，避免点开陌生链接就被拉进房间。
- **目标用户**：通过微信 / 群聊拉人的组织者。
- **预期效果**：从"报房号—抄房号—输房号"三步变一步；复制失败自动降级为只读链接框。

### 2.3 设置中心（FR-13）

- **范围**：音效开关、音量（作用于 WebAudio 主增益，即时生效）、减少动效（`body.reduce-motion` 叠加在系统 `prefers-reduced-motion` 之上）、操作提示显隐、清空本地数据。
- **目标用户**：需要静音的办公室玩家、晕动症敏感用户、觉得提示碍眼的老玩家。
- **预期效果**：偏好只存本机不上传；刷新 / 二次访问保持生效。

### 2.4 本地战绩（FR-14）

- **范围**：只统计本机最近 20 局；记录模式/胜负/淘汰/时长/人数；**不记录**昵称、房号、对手 id、聊天内容等任何可识别他人的信息；支持导出 JSON。
- **目标用户**：想看自己胜率变化的玩家。
- **预期效果**：结算页之外多一个轻量的回顾入口；数据完全在本地，清退即焚。

### 2.5 服务端加固（FR-15 / NFR-6 / NFR-9）

- **范围**：见 §4。全部为**入口防御**，不触碰游戏规则与模拟循环。

## 3. 关键设计与代码结构

新增 4 个客户端模块 + 1 个服务端模块，全部延续既有约定：IIFE 封装、挂 `window.*`、零构建、零全局污染（仅模块命名空间）：

```
public/js/store.js    → window.Store    设置/战绩的 schema 校验、版本迁移、降级
public/js/chat.js     → window.Chat     聊天 UI + 客户端限流
public/js/share.js    → window.Share    URL 同步 + 剪贴板降级链
public/js/panels.js   → window.Panels   模态层（设置/战绩）+ 焦点管理
server/validate.js    → CommonJS 纯函数 输入校验 + 令牌桶（零依赖）
```

- **`store.js` 是 UMD 双端模块**：浏览器挂 `window.Store`，Node 里 `require` 直接单测（`test/store.test.js`），与 `motion.js` 同一手法。
- **`main.js` 只做接线**：`Net.on('chat'/'room'/'left'/'game'/'over')` 分发到各模块；`S.matchStartAt` / `S.lastOverKey` 两个状态字段支撑战绩记录与去重。
- **模态层与界面状态机解耦**：`#screenSettings` / `#screenStats` 不进 `el.screens`，由 `Panels` 独立管理显隐；`showScreen` 真正切换界面时才收起弹层，房间内的周期广播不会误关设置。

## 4. 输入校验、异常处理与边界情况

### 4.1 服务端校验层（`server/validate.js`）

| 校验 | 规则 | 拒绝后果 |
| --- | --- | --- |
| WebSocket 帧大小 | `maxPayload: 16KB` | 超限帧被拒，连接报错但不崩进程（每连接挂 `ws.on('error')`） |
| hello / adoptName 昵称 | `sanitizeName`：去控制字符、压缩空白、**Unicode 码点**截 12 字（服务端宽于客户端 8 字，兼容旧客户端） | 截断而非拒绝，连接保持 |
| join 房号 | `normalizeCode`：`/^[A-HJ-NP-Z2-9]{4}$/` | 回 `err {code:'BAD_CODE'}`，客户端 toast |
| input seq/dir | `normalizeSeq`（0…2³¹−1）+ `isValidDir` + `bomb === true` | 整条消息丢弃（预测靠超时重发自愈） |
| chat 文本 | `normalizeChat`：40 码点、去控制字符、压空白 | 空文本直接忽略，不回错误 |
| 房间数 | `MAX_ROOMS`（默认 500） | 回 `err {code:'ROOM_LIMIT'}` |
| 房号分配 | 去掉 I/O/0/1 的 32 字符集，冲突重试，耗尽返回 null | 建房请求安全失败，客户端提示 |

### 4.2 限流（令牌桶，`createBucket`）

| 桶 | 参数 | 作用 |
| --- | --- | --- |
| 每连接消息桶 | 容量 120，120/s 回填 | 洪水攻击触发 `floodStrikes`（>500）→ `close(1008,'flood')`；正常重连风暴（约 300 帧）不会误伤 |
| 每连接聊天桶 | 容量 4，0.75/s 回填 | 单人最多连发 4 条，之后约 1.3s 恢复 1 条 |
| 客户端本地冷却 | 700ms | 省流量 + 挡手抖连点 |

时间增量在桶内封顶 5 秒（`Math.min(dt, 5)`），长时间挂起的连接不会攒出"无限额度"。

### 4.3 存储边界（`store.js`）

- **读**：JSON 损坏 → 视为空；**未来版本数据**（`v > 1`）→ 读默认值且**永不回写**（防止旧代码把新 schema 洗掉）。
- **写**：隐私模式 / 配额满抛错 → 自动降级内存态，`available=false`，页面 toast 提示一次。
- **战绩上限**：20 条，超出丢弃最旧；`addMatch` 按 `id` 去重。
- **结算去重**：`startedAt + durationMs + results.length` 组成 `lastOverKey`，断线重连后服务端重发同一 `over` 不会写两条。

### 4.4 客户端健壮性

- **XSS**：聊天与战绩的玩家可控文本全部 `textContent` / 预格式化数字渲染，`test/enhance.js` D8/D9 验证 `<img onerror>` 与 `<script>` 注入不执行。
- **IME**：输入法组合期间不裁剪、不发送（`compositionstart/end` + `isComposing`）。
- **剪贴板降级链**：`navigator.clipboard`（安全上下文）→ `execCommand('copy')`（隐藏 textarea）→ 只读输入框手动复制；三层均不抛错到顶层。
- **URL**：`URLSearchParams` / `history.replaceState` 均包 try/catch（`file://` 打开也不崩）。
- **弹层输入穿透**：`keydown/keyup/placeBomb/触屏按下` 全部先查 `Panels.isOpen()`；弹层开着时方向键、空格不会作用到背后的对局。
- **网络队列**：断线期间消息排队（上限 20），满时**优先丢最旧的聊天**，绝不挤掉建房 / 加入请求。

### 4.5 服务端进程级

- `wss.on('error')`、`server.on('error')`（`EADDRINUSE` → 退出码 1）；
- `broadcast / sendTo / send` 全部 try/catch：向已死 socket 写入不再抛未捕获异常；
- 会话清扫器每 60 秒跑一次且 `.unref()`，不阻止进程退出；
- `/health` 返回 `{ok, rooms, sessions, uptime}` 供探活。

## 5. 性能考量

| 点 | 措施 |
| --- | --- |
| 聊天渲染 | 每条一个节点、DOM 上限 50 条（超出移除首条），`scrollTop` 直落底部；不含任何每帧逻辑 |
| 模态层 | 打开 / 关闭各一次性 DOM 操作；焦点陷阱只处理 Tab 键，其余按键仅做 `isOpen()` 早退 |
| 战绩 | 只在结算与打开弹层时读写；列表 20 条上限，无滚动监听 |
| 限流 | 令牌桶 O(1)，无定时器（惰性按时间差回填），不进 50Hz 模拟循环 |
| 设置 | 音量拖动 180ms 防抖落盘，`change` 时立即落盘一次 |
| 布局 | 新增 UI 全部在既有 overlay 内部，不触碰 `layout.js` 的棋盘测量链路（响应式验收 184 项全过） |
| 网络开销 | 聊天消息仅等待阶段存在，单条 ≤ 数百字节，受 16KB 帧上限约束 |

## 6. 可扩展性

- **新设置项**：在 `store.js` 的 `DEFAULTS` / `normalizeSettings` 加字段 + `panels.js` 加一行渲染与事件即可，版本号 `SCHEMA` 不用动（字段级容错）。
- **新快捷语**：`chat.js` 顶部 `QUICK` 数组加一项。
- **聊天升级为表情/贴纸**：协议里 `text` 字段换成结构化对象，服务端 `normalizeChat` 换成白名单校验函数，广播链路不变。
- **观战 / 回放**：`over` 消息已带上 `startedAt / durationMs / mode / humans / bots`，为后续战绩聚合预留了字段。
- **校验复用**：`server/validate.js` 是纯函数模块，可直接被未来的 HTTP 接口复用。

## 8. 未纳入 v1.1 的方向（与范围决策）

- **观战**：`Room.broadcast` 只遍历 `players`，观战需要非对称广播与席位语义，涉及快照外的新消息面，留待 v1.2。
- **聊天历史持久化 / 离线消息**：与"轻聊天"定位冲突，且需要服务端存储。
- **账号体系 / 跨设备战绩**：本地战绩刻意不做云同步，避免引入隐私与合规面。
