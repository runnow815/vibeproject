# 泡泡对战 · 联机炸弹对战

一个《Q版泡泡堂》风格的 2～4 人对战小游戏：在地图里走位、放炸弹、炸开箱子捡道具，
被炸中会被「炸晕」，队友/对手碰到晕住的你决定你是被救还是被淘汰。

支持三种对局：**玩家对战**（纯真人）、**人机对战**（1 真人 + AI）、
**混合对战**（1–4 真人 + 1–4 AI，总数 ≤ 4，可 2v2）。

- 前端：原生 HTML + CSS + Canvas 2D（零框架、零图片资源，图形全部代码绘制）
- 后端：Node.js + `ws`（WebSocket），只依赖一个包
- 联机：服务端权威模拟 + 客户端预测 + 快照缓冲插值
- AI：跑在服务端的机器人，和真人走**完全相同的输入通道与规则判定**

> 道具图鉴见 [docs/道具清单.md](docs/道具清单.md)（含原作道具效果、获取方式与本作实现对照）。
> 项目文档：[需求文档](docs/需求文档.md)（功能/非功能需求、用户与场景）、[架构文档](docs/架构文档.md)（系统设计、模块划分、选型与交互）；两份文档用同一套 `FR-*` / `NFR-*` 编号双向追踪。

## 快速开始

```bash
npm install
npm start
# 打开 http://localhost:3000
```

想两个人一起玩：

1. 同一台电脑：开两个浏览器标签页（`sessionStorage` 按标签页隔离，天然算两个玩家）。
2. 同一个局域网：手机/另一台电脑访问 `http://<你的内网IP>:3000`（服务默认监听 `0.0.0.0`）。
3. 一个人点「创建房间」，房间页点「复制邀请链接」发给对方（或直接告知 4 位房间号）；或双方都点「快速匹配」。
4. 想单人练手：首页选「人机对战」，挑好难度和 AI 数量后点「快速匹配」立刻开局。
5. 想和朋友一起打 AI：选「混合对战」，AI 数量决定真人席位（AI 2 个 → 2 个真人席位）。

## 玩法

| 操作 | 键盘 | 手机 |
| --- | --- | --- |
| 移动 | `WASD` / 方向键 | 左下方向键 |
| 放炸弹 | `空格` / `J` | 右下圆形按钮 |
| 挣脱（被炸晕时） | 狂按方向键 | 狂点方向键 |

规则要点：

- 炸弹放下后 **2.4 秒**引爆，炸出十字冲击；冲击会被石墙挡住，炸开木箱后停止。
- 木箱有 36% 概率掉落道具：**炸弹+1**（同时可放数量）、**火力+1**（冲击长度）、**速度+1**。
- 被冲击命中不会直接死，而是被**炸晕**：4.2 秒内没人碰你，眩晕结束即出局；
  期间任何人走到你所在的格子都会补刀 —— 1v1 里这就是收割。
  2v2 时队友碰到你是**救援**（解除眩晕 + 0.9 秒无敌帧），只有对手碰到才是补刀。
- 开局有 **2.2 秒倒计时** + 1.6 秒出生保护。
- 最后存活者获胜；3 分钟到点则按淘汰数排名。2v2 时按队伍判定（一队全灭即结束，时间到比队伍总淘汰数）。

## 三种模式与人数配置规则

| 模式 | 真人 | AI | 总人数 | 说明 |
| --- | --- | --- | --- | --- |
| 玩家对战 `pvp` | 2–4 | 0 | 2–4 | 纯真人，可 2v2 |
| 人机对战 `pve` | 1 | 1–3 | 2–4 | 单人练习，点「快速匹配」直接开局 |
| 混合对战 `hybrid` | 1–4 | 1–4 | ≤ 4 | 真人与 AI 同场，可 2v2 |

混合模式的硬约束是 `1 ≤ 真人 ≤ 4`、`1 ≤ AI ≤ 4`、`真人 + AI ≤ 4`，展开后只有 6 种合法组合：

| 真人 | AI | 总数 |
| --- | --- | --- |
| 1 | 1 | 2 |
| 1 | 2 | 3 |
| 1 | 3 | 4 |
| 2 | 1 | 3 |
| 2 | 2 | 4 |
| 3 | 1 | 4 |

> 因为至少要 1 名真人，`AI = 4` 在混合模式里不可能出现（4 + 1 > 4），
> 所以混合模式的 AI 实际可选 1–3；4 个 AI 只会出现在"0 真人"的观战场景，本项目不做。
> 服务端 `server/lineup.js` 的 `validateLineup()` 会对越界组合直接返回错误文案，
> `VALID_LINEUPS` 固化了上面这 6 种组合，前后端与测试共用同一份规则。

### 房间与匹配逻辑

- 建房时配置的是 **AI 数量**，真人席位 = `4 - AI`（人机对战固定 1 席）。
  等待界面会直接把 AI 当作"已占位"的席位显示出来。
- **快速匹配**：按 `模式 + AI 数量 + 难度 + 是否分队` 四元组，优先并入"还在等待、且仍有真人席位"的房间；
  找不到就新建。
- 混合模式的新建房带 **12 秒自动开局倒计时**：人没凑齐就按当前真人 + 配置的 AI 开局，
  不会让玩家无限空等；中途有人加入就一起开。
- 人机对战不走匹配，收到请求立刻建房并开局。
- 真人席位满时拒绝加入，并明确提示原因：`真人席位已满（已配置 2 个 AI）`。

### 队伍分配逻辑

仅在**总数正好 4 人**且勾选「2v2 分队」时生效，否则自动降级为混战（并在界面上说明）。

1. **真人先蛇形轮转**：按加入顺序 `0→蓝, 1→红, 2→蓝…`，保证两队真人数量差 ≤ 1。
2. **AI 再补位**：每个 AI 分给当前人数较少的一队（相等时补蓝队），保证两队总人数差 ≤ 1。
   例：`1 真人 + 3 AI` → 蓝队 1 真人 + 1 AI，红队 2 AI；`3 真人 + 1 AI` → 2+1 对 1+1。
3. **出生角按队伍成组**：蓝队用左侧两个角 `(1,1)` / `(1,11)`，红队用右侧 `(13,1)` / `(13,11)`，
   同队相邻、两队隔图相望；混战则 2 人用对角、3–4 人依次占四角。
4. 队伍内真人保持自己的颜色，脚下多一圈队伍色；HUD 与结算里显示「蓝/红」标签。

### AI 是怎么做的

`server/bot.js`。核心原则：**AI 没有任何特权**，它只是另一个输入来源。

- 每次思考先构建**危险图**：对所有活跃炸弹用 `blastPreview()` 算出爆炸范围，记下每个格子的挨炸时刻，
  连锁引爆按 `上游引爆时刻 + 80ms` 传播。
- 站在危险格 → 用**带时间预算的 BFS** 找"爆炸结束后依然安全"的落脚点，优先不是死胡同的格子；
  移动中按"即将到达的格子"规划，到格即重新决策，不会左右横跳。
- 安全时评估脚下放炸弹的价值（能炸到人 / 能炸开箱子、会不会炸到队友），
  并且**先在虚拟地图上验证"放完逃得掉"**才落子。
- 没事做就去捡最近的道具、追最近的敌人；都没有就去最近的"可炸箱位置"开图。
- 难度只影响反应间隔、失误率、搜索深度，**不给 AI 加数值**，所以困难 AI 也不会凭空多一格火力。

## 技术方案

```
┌──────────────┐   输入意图 {seq, dir, bomb}     ┌──────────────────┐
│   浏览器 A    │ ───────────────────────────────▶ │                  │
│  Canvas 渲染  │                                  │   Node.js 房间服  │
│  本地预测     │ ◀─────────────────────────────── │  50Hz 权威模拟    │
└──────────────┘   权威快照 {players,bombs,...}    │  16.7Hz 广播      │
┌──────────────┐                                  │                  │
│   浏览器 B    │ ◀─────────── 同一份快照 ───────── │  内存态，无数据库  │
└──────────────┘                                  └──────────────────┘
```

- **服务端**：每个房间一个固定步长循环（`setInterval` 20ms = 50Hz）推进模拟，
  每 3 个 tick 广播一次快照（≈16.7Hz）；有爆炸/拾取等事件时额外立即广播。
- **客户端**：`requestAnimationFrame` 渲染（跟随显示器刷新率），自己的角色做本地预测，其他玩家做缓冲插值。
- **传输**：纯 JSON over WebSocket。一局 4 人时下行约 8～15 KB/s，远低于常见实时游戏阈值。

## 联机同步思路

### 1. 服务端权威（Authoritative Server）

所有规则判定都在服务端：能不能走、能不能放炸弹、冲击打到谁、谁出局、掉落什么道具。
客户端只能上报「我现在想往哪走 / 我想放炸弹」，无法直接修改位置或血量。
这样即使客户端改代码，也无法瞬移、无限炸弹或伪造击杀。

### 2. 客户端预测（Client-side Prediction）

纯服务端权威的代价是「按下去要等一个 RTT 才动」，50ms 延迟就明显发涩。所以：

- 玩家按下方向键 → **在按键事件里立刻**用同一套移动规则开始位移（不等下一帧），
  同时把 `{seq, dir}` 发给服务端；
- 服务端把 `lastSeq`（已处理的最后一条输入序号）放进快照回传；
- 校正策略（见下方"移动手感"）：**只要有一端还在移动就认为这是延迟，不校正**；
  两端都静止且确实差了半格以上 → 只对齐逻辑格，渲染位置用可衰减的偏移滑过去；
  只有误差 > 2.4 格（重连、复活）才硬吸附。

放炸弹也做了乐观渲染：本地先画出来，服务端确认后由权威列表接管，
若 800ms 内没被确认（例如因为容量不足被拒）就自动删除这个"幽灵炸弹"。

### 3. 远端插值（Snapshot Interpolation）

别的玩家每 16.7Hz 才收到一次位置，直接渲染会一跳一跳。现在是：

- 每个远端玩家维护一串「带到达时间的样本」`{t, x, y}`（保留 12 个）；
- 渲染时回放 **90ms 前**的状态：在相邻两个样本之间做**线性插值**，
  所以位置是连续直线，不受快照频率和本机帧率影响；
- 短暂越过最新样本时，按最后一段的速度外推（最多 120ms），避免"卡住不动"；
- 样本间跳变 > 3 格（重连、传送）则丢弃历史重新开始。

> 早期的做法是"指数平滑追目标点"：每个快照到达时位置会跳一下再收敛，
> 在 60ms 一个快照下看起来就是一格一格地顿。线性插值 + 固定延迟彻底消掉了这个现象，
> 代价是远端玩家比真实位置晚 90ms —— 这是所有实时游戏都在付的账。

### 4. 状态最小化

- 地图只在开局下发一次（`Uint8Array` 压缩成数组），之后只发**增量**：`changes: [[x,y,item]]`。
- 炸弹只发剩余引信时间 `left`，冲击波只发格子列表 + 存活时长 `age`，客户端自己淡出。
- 玩家状态用短字段名，一帧快照几百字节。

### 5. 房间与容错

- 房间号 4 位（去掉了容易混淆的 `I/O/0/1`），`快速匹配`优先塞进同配置、未满的等待中房间。
- 断线不立刻踢人：保留 12 秒宽限期，凭 `sessionStorage` 里的玩家 id 重连即可**恢复到进行中的对局**
  （服务端补发当前地图 + 全量快照）。
- 主动退出 / 宽限期超时 → 服务端直接判负，避免残局被一个不动的"活人"卡死。
- AI 不占用连接、不需要断线处理：它们只存在于 `Game.players` 里，人走了照样打完整局。

## 实现要点

### 移动手感：为什么原来会"卡顿"，怎么修的

原来的移动有三个独立的问题，叠在一起就是"走两步顿一下"：

1. **每格都丢时间（主因）。** 旧逻辑到达一格时把 `moveStart` 重置成"当前帧时间"，
   等于每格丢掉 `帧时间 - 剩余时间` 的零头。60fps 下每格实际耗时在 **150～167ms** 之间随机，
   帧率越低越慢（144fps 时 152.8ms、60fps 时 157.4ms），走起来就是有节奏的一顿一顿。
   现在用 `Motion.advance()`：到格时以**精确到达时刻** `moveStart + moveDur` 作为下一格起点，
   把余量继续算进去，每格恒定 150ms，30/60/120/144fps 完全一致。
2. **回包硬吸附（橡皮筋）。** 旧逻辑收到快照只要"服务端已静止且差了 0.5 格"就直接把本地位置吸过去。
   有网络延迟时本地预测本来就该领先半格，于是人被往回拉一下再往前走。
   现在只要有一端还在移动就认定为延迟、不校正；真不一致时只对齐逻辑格，
   渲染位置用一个 150ms 内衰减完的偏移滑过去，视觉上没有跳变。
3. **远端指数平滑（一格一格地顿）。** 换成"90ms 延迟 + 样本间线性插值"，见上一节。

另外两处配套改动：

- **服务端同样丢余量**：`tryStartMove(p, at)` 用上一格的到达时刻接格，不再每个 tick 丢 20ms，
  远端玩家看到的权威位置因此是匀速的。
- **按键即时起步**：方向键的 `keydown` 里就调 `kickLocal()` 开始位移，中间不再等一帧 rAF。

实测（`test/smooth.js`，无头 Edge 逐帧采样）：速度波动 **0.0%**、运动中停顿帧 **0**、
单格耗时 **150ms**、按键到起步 **≤ 14ms（1 帧以内）**。

### 其他

**网格 + 连续坐标双表示。** 碰撞和判定用整数格 `cellX/cellY`，广播和渲染用浮点 `px/py`。
移动不是"插值到目标点"，而是"一格一格地走"：每格耗时 `150ms × 0.82^速度等级`，
走完一格立刻接下一格，所以按住方向键是连贯的，而每一格的到达时刻都是确定的。

**爆炸算法。** 以炸弹为中心向四个方向逐格推进：遇到石墙停、遇到木箱炸掉后停、
遇到别的炸弹就排队引燃（连锁爆炸）。冲击格子再统一做一次玩家命中判定。

**炸晕而不是击杀。** 命中只标记 `trapped` 并开始计时，把"能不能补刀"交给玩家操作，
这是泡泡堂最核心的博弈点，也顺带降低了暴力感。

**格子级细节。** 有炸弹的格子不可进入（自己的也不行），所以放完要绕开；
移动中放炸弹取"离得最近的一格"，客户端和服务端用同一套 `cellOf` 逻辑，保证预测不会错位。

**手感调参集中。** 引信时长、眩晕时长、移动速度曲线、掉落概率都集中在 `server/game.js` 顶部常量，
改数值即可调平衡，不用翻代码。

## 美术：炸弹模型（Q 版）

零图片，全部 Canvas 代码绘制，和角色的圆润风格对齐：

- **炸弹**：深色球体（径向渐变 + 厚描边）+ 顶部金属盖 + 弯曲引线 + 闪烁火花；
  大椭圆高光是 Q 版的关键。剩余时间 < 30% 时脉动加快、加红色警示光晕，外圈还有引信进度环。
  有人站在炸弹上时整体下移 9px，保证不被角色完全挡住。
- **爆炸**：中心火球（白 → 亮黄 → 橙 → 红）+ 向外扩散的冲击波环 + 火舌，
  四个方向是"沿方向铺满整格"的冲击臂（横向宽而扁、纵向窄而高），带白色内芯和迸出的火星。
- **炸晕**：眼睛变成 `XX`、身体小幅摇晃、头顶三颗星星绕圈、脚下金色计时环，名字自动上移让位。

## 响应式布局

桌面、平板、手机（含横屏）都能直接玩，完整说明见 [`docs/响应式布局.md`](docs/响应式布局.md)。

| 断点 | 宽度 | 关键变化 |
| --- | --- | --- |
| `xs` | < 480px | 创建/加入改为纵向堆叠；顶栏只留房间号与状态点；对手卡只显示头像+名字 |
| `sm` | 480–767px | 恢复同行布局；正文 12.5px；棋盘上限 560px |
| `md` | 768–1023px | 面板 440px；棋盘上限 680px；HUD 单行铺开 |
| `lg` | 1024–1199px | 棋盘上限 700px；触屏时摇杆移到左右两侧 |
| `xl` | ≥ 1200px | 棋盘 + 右侧 HUD 两栏；≥1440 / ≥1600 再放大到 780 / 880px |

另有高度断点（手机横屏 `≤560px`、平板横屏 `≤900px`）和能力查询（`pointer: coarse`、`prefers-reduced-motion`、`prefers-contrast`）。

要点：

- **棋盘尺寸不靠 vh 魔法数字**。`js/layout.js` 读取 `.stage` 实际可用宽高、HUD 占位和 CSS 变量 `--board-max`，三者取小后写入 `--board-w`，两趟求解（HUD 换行会改变自身高度）。320×568 到 1920×1080 实测棋盘比例恒为 15:13，从不溢出。
- **按优先级降级**：P0 棋盘（只缩不裁）→ P1 摇杆 → P2 自己的状态卡 → P3 对手属性 → P4 顶栏细节 → P5 提示文案。
- **触控**：所有可点元素 ≥44px，`touch-action` 分离"移动"与"滚动"，摇杆位置随朝向在"下方 ↔ 左右两侧"切换（横屏改两侧可让棋盘多出约 150px 高度），并处理了安全区、软键盘、iOS 输入框缩放。
- **可读性**：正文 ≥12px，输入框 16px，说明文字对比度提到 4.6:1；允许双指缩放（去掉了 `user-scalable=no`），补齐 `:focus-visible`、`aria-pressed`、`aria-live`、减少动效偏好。
- **画布降级**：`viewScale < 0.58` 时不再画角色名字（会糊成一团），只给自己画定位箭头，名字交给 HUD。

## 测试

```bash
npm test                  # 核心逻辑测试（54 项断言）
npm run test:server       # v1.1 校验/存储/聊天/健壮性（42 项断言）
npm run test:browser      # 浏览器实测：平滑度 + Canvas 视觉帧 + 9 视口响应式 + v1.1 增强（45 项）
node test/lineup.test.js  # 只跑人数配置与队伍分配
node test/bot.test.js     # 只跑 AI 行为（真实计时，约 6 秒）
```

`net.test.js` / `hybrid.test.js` 会各自拉起一个独立端口的服务，用真实 WebSocket 客户端对打，
并断言两端收到的权威状态（包括 AI 的坐标）**完全相同**（这是"实时同步"最直接的验证）。

`test/smooth.js` 在真实浏览器里按住方向键逐帧采样角色坐标，输出速度波动、停顿帧、
单格耗时和按键响应延迟；`test/canvas.js` 直接调 `toDataURL()` 取当前帧，
绕开截图工具的合成器缓存，用来验收炸弹/爆炸/眩晕三套美术。

`test/responsive.js` 覆盖 320×568 到 1920×1080 共 9 个视口（含手机横屏、平板横竖屏），
断言无横向溢出、棋盘完整可见且比例恒为 15:13、不与 HUD/摇杆重叠、正文 ≥12px、
触控目标 ≥44px，并输出每个视口的实际棋盘尺寸。

`test/enhance.js` 验收 v1.1 体验增强：设置中心（焦点陷阱 / inert / Esc / 持久化）、
本地战绩（渲染 / 汇总 / 二次确认清空）、邀请链接（`?room=` 预填 / 无效清理 / 剪贴板降级）、
房间聊天（发送回显 / 字数统计 / XSS 注入不执行）、对局中聊天禁用。

## 可继续扩展的方向

- AI 分层配合：2v2 里让 AI 增加"跟随队友 / 给队友让路 / 集火同一目标"的协同策略。
- 道具扩展：踢炸弹、投掷炸弹、遥控炸弹（数据结构已经预留 `power`/`owner`）。
- 观战与回放：快照本身就是可序列化的帧序列。
- 聊天增强：表情贴纸、对局中快捷信号（协议已预留 `text` 字段结构化空间）。
- 横向扩容：房间状态在内存里，多进程需要按房间号做一致性哈希。
